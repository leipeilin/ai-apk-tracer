## 1. 评审结论摘要

两份方案结构完整、现状锚点大体准确（findings 端点先例、NotFoundError→404 映射、observations 落盘时机均经代码核实成立），范围切分与回退设计清晰，具备可实施基础。但存在三处须修订项：排序第一键偏离上级依据且归因失实（实施稿引用的"任务要求"与 T2.10 任务行原文不符）；deep_dive 投影含模型中不存在的字段（consistency_downgraded 属核验 agent）；前端 eslint 门禁引用了项目并不存在的工具链。验收方案可判定性总体良好（A-8 预置数据路径可行、A-10 注册条件正确），补齐响应键名统一与前端轮询口径后可放行。

## 2. 问题清单

**【R-1】【高】** 排序第一键偏离上级依据且归因失实——任务行原文为"按置信度排序"、大纲 §2.0/§5.4 为"按置信度/引用完整度排序"，均无"按 deep_dive 证据排序"；且深挖仅对 partial 执行（T2.8 明确 unverified 不送深挖），以深挖证据数为第一键会使带证据 partial 沉底所有 unverified，系统性重演大纲 §6"unverified 候选被埋没"风险。
证据：实施计划 79 行；大纲 179/526 行；实施稿排序节。
修订建议：置信度为主键，deep_dive 证据数降为同置信度内次级键；删除失实归因；A-2/A-3 用例同步重写。

**【R-2】【中】** deep_dive 投影引用不可达字段（consistency_downgraded 不在 ExplorerCandidateDeepDive——属核验 agent 结果）。
证据：ai_models.py:473-491；verify_agent.py:229/391。
修订建议：替换为真实字段（unverifiable_evidence_count/evidence_truncated_count）。

**【R-3】【中】** eslint 门禁引用不存在的工具链（frontend 无 eslint 依赖与 script；check-all.sh 前端仅 npm run build）。
证据：frontend/package.json:6-26；check-all.sh:4-6。
修订建议：门禁如实改 tsc+build；eslint 若需属新基建另行立项。

**【R-4】【中】** 前端拉取与轮询策略缺失（FindingsPanel 是 props 模式由 RunDetailPage 轮询；面板自取 runId 一次性拉取会在 explorer 阶段完成前停留空态）。
证据：FindingsPanel.tsx:56；RunDetailPage.tsx:18-32；explorer.py:129-130。
修订建议：复用 usePolling（run active ? 2000ms : 一次拉取）；补 loading/error 态。

**【R-5】【中】** 任务行"call_tree 可选落盘注册"遗漏处理。
证据：实施计划 79 行；实施稿未提。
修订建议：核实现状后补注册或显式排除。

**【R-6】【低】** 响应键名两文档不一致（{queue} vs {candidates}）。
修订建议：统一（entries）。

**【R-7】【低】** hop_count_total 非 validation 字段（须从 len(hops) 派生）——投影应注明派生口径。
修订建议：chain.hop_count 单点表达。

**【R-8】【低】** 三档徽章配色需复用现有色板或补 styles.css（现仅 severity-\*/status-\*/receiver-tier-\* 系列）。
修订建议：复用 receiver-tier-badge 样式 + 现有色板变量。

**【R-9】【低】** counts.total（含 validated）与列表行数口径差异未说明；验收章节编号跳跃。
修订建议：注明口径 + queue_length；修编号。

## 3. 认可项

1. 404 语义锚点准确（NotFoundError 经 AppError handler 映射；get_run 校验模式）。
2. 空态 200（非 404）决策正确（探索轨默认关闭是常态）。
3. observations 补注册条件成立（explore_all 末尾无条件写盘；守卫兼容历史 run）。
4. validated 仅计数不进列表（D1）与大纲 §5.4 一致。
5. counts 含 pending 正确（validation.status Literal 含 pending）。
6. A-8 可判定（ingest 响应含 manifest_path——测试可直写 run_dir 后 GET）。
7. 服务端预排序 + sort_keys 透明化可审计。
8. 响应体积控制合理（≤50 候选 + 投影脱全量）。
