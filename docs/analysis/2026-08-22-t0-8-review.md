## 1. 评审结论摘要

设计稿主体与既有 v2/v3 迁移机制同构、升级路径无损、范围边界清晰，总体可接受。存在 1 项关键缺口（`batches.ai_skipped_count` 无 run 级落库列可聚合）、1 项高（FK 事实与文档描述不符：`connect()` 已在 L54 开启）、以及大表 ALTER/测试叠加路径/API 兼容等中低问题。修订后进入 T1.1。

## 2. 问题清单

| 编号 | 严重度 | 问题描述 | 证据 | 修订建议 |
|---|---|---|---|---|
| R-1 | 高 | `connect()` 已在 L54 执行 `PRAGMA foreign_keys=ON`，但实施稿/验收稿仍将"FK 未开启"当兜底场景（虚构负例） | `repository.py:54` | 删除 FK-off 冗余风险与 N-5，明确 FK 恒开启 |
| R-2 | 关键 | `batches.ai_skipped_count` 声明聚合自 run 级 `ai_skipped_by_batch_budget`，但 runs v4 迁移仅加 asset_id/batch_id，无此列，聚合数据源缺失 | 实施稿 §3.3 vs `runs` L79-95 | v4 为 runs 补 `ai_skipped_by_batch_budget INTEGER NOT NULL DEFAULT 0` |
| R-3 | 中 | runs `ALTER TABLE ADD COLUMN` 重建表持排他写锁，大库耗时/阻塞未评估、测试未含大数据场景 | 实施稿 §3.4/§3.7 | 补大表说明 + 测试项 |
| R-4 | 中 | 升级测试只构造 v3 形状库，未覆盖含 v2/v3 迁移记录的叠加路径与 v4 中断重试 | 实施稿 §3.7 vs 既有 test L95-136 | 复用 legacy 构造，补叠加路径 + 中断重试用例 |

## 3. 认可项

- 迁移接入与 v2/v3 完全同构；`DATABASE_SCHEMA_VERSION` 3→4 命名一致。
- `apk_sha256 UNIQUE` 防重、可空外键 `ON DELETE SET NULL` 保留 run 证据的 retention 语义。
- 升级路径逐条可执行、旧库无损；SQL 参数绑定与幂等符合红线。
- 范围边界清晰（未越界 T1.1）。
