## 第一部分：实施方案

### P7（E6）：SSL/TrustManager 正则改方法体提取

**问题**（评审 E6，审查报告核实行号）：
- `WEBVIEW_SSL_ERROR_IGNORED`：`onReceivedSslError\s*\([^)]*\)\s*\{[^}]{0,800}?\w+\s*\.\s*proceed\s*\(` —— `[^}]` 停在首个 `}`，`if (cond) { handler.cancel(); } handler.proceed();`（嵌套块后放行，真实 APK 常见写法）系统性漏检；
- `TRUST_MANAGER_ALL_ACCEPT`：`checkServerTrusted\s*\([^)]*\)\s*\{([^{}]{0,400}?)\}` —— `[^{}]` 不跨嵌套块，且不识别裸 `return;` 形态的"无校验"实现（不抛异常 = 接受任意证书）。

**方案**：新增 `_matching_brace_end`（花括号深度计数配对，模仿既有 `_matching_paren_end`——sanitized 已剔除注释/字符串，深度计数安全）：
- SSL：方法头定位（`onReceivedSslError(...) {`）→ 花括号配对提取完整方法体 → 体内搜 `\w+\s*\.\s*proceed\s*\(`——嵌套块内/后均可检；每方法一候选（行号=方法头）；
- TRUST：同款方法体提取 → body 为空（sanitize 后纯注释体即空串）**或裸 `return;`**（`re.fullmatch(r"return\s*;", body)`）命中；含任何实质语句（含 throw）不命中（交 AI 复核）。

**HOSTNAME_VERIFIER 的取舍**：保持"单语句恒真"语义（`{ return true; }` 本就被覆盖；多分支全 true 的路径分析复杂度/误报率不划算，留 AI 复核），仅低成本扩展 `Boolean.TRUE` 恒真形态。

### P8（E5）：弱加密覆盖扩充

**问题**（评审 E5）：
- `WEAK_CIPHER_ECB` 只匹配 `"AES/ECB/...` 字面前缀——`Cipher.getInstance("AES")`（默认 provider 即 AES/ECB/PKCS5Padding，最隐蔽写法）漏检；
- 弱算法/弱哈希族（DES/DESede/3DES/RC4、MD5/SHA-1）零规则覆盖。

**方案**：
1. `WEAK_CIPHER_ECB` 扩双模式：显式 `"AES/ECB/..."` 前缀 + 裸 `"AES"` 单参（`["']AES["']\s*\)`，与前者无重叠——斜杠要求互斥），description 区分"显式 ECB"与"隐式 ECB"；
2. 新规则 `WEAK_CIPHER_ALGORITHM`（crypto/L2/medium）：
   - `Cipher.getInstance("DES|DESede|3DES|RC4...` transformation 前缀匹配（`DESede` 被 `DES` 前缀覆盖）；
   - `MessageDigest.getInstance("MD5"|"SHA-1"|"SHA1")` 弱哈希（MASVS-CRYPTO-1）；
   - `SHA-256`/`AES/GCM` 等现代算法不命中；安全相关性定级（口令存储 vs 完整性校验）留 AI 复核。

**管线接入**：RULE_META（34 条）/ GLOBAL_CODE_RULES（12 条）/ GLOBAL_RULE_TERMS（FTS 词项 `Cipher.getInstance, MessageDigest.getInstance, DES, RC4, MD5, SHA`——SHA-1 在 unicode61 下切为 SHA+1 两 token，词项用 SHA 由正则精判）/ detect.py（argv 传 input.json 模板）/ 协议断言 33→34。

### 风险与边界声明

- P7 是**召回扩展**（嵌套块/裸 return 形态新增可检），旧已检形态行为不变（测试锚定）；
- P8 的裸 "AES" 判定为字面量精确匹配——`"AES "` 带空白或大小写混合（`"aes"`）经 `\s*\)` 与 re.I 覆盖；transformation 变量传递仍不覆盖（AI 复核兜底，rule.yaml 声明）；
- HOSTNAME_VERIFIER 保持单语句语义是有意取舍（非遗漏）。

### 3. 实施中修正的缺陷（自我核验记录，替代子代理核验）

1. **detect.py 模板错误**：新规则初版误用 stdin 读取模式，而 `rule_runner` 以**argv 传 input.json 路径**（stdin=DEVNULL）——导致协议测试与 `test_manual_review_regressions`（同走 RuleRunner）两处失败（`JSONDecodeError: line 1 column 1`）。经逐规则串行复现定位，改为与 P5 一致的 argv 模板后消除。*这佐证了模板复制而非重写的必要性。*
2. **行号/文本语义**：SSL/TRUST 新逻辑的 `text` 取方法头原文片段（`code[header.start():header.end()]`），行号=方法头行——与旧行为（匹配点行号）语义一致（旧匹配点即方法头内）。
