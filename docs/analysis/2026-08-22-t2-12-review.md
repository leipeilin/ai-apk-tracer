## 1. 评审结论摘要

方案对大纲 §2.7 分流语义、M0 §4.2 适配层要求、三本账预算架构的静态对照基本属实（分流判定、预算接线、checkpoint 隔离、回退矩阵均可落地，且有 deep-dive/explorer 先例支撑）。但 **D5 的核心论证存在事实错误**：聚合层 path#window 回查只作用于 slice_refs 条目，verify 分支传原始 slice 使 slice_refs 不含合成窗口 ID，适配证据将在聚合层被全量判 CONTEXT_ID_NOT_FOUND。叠加 analysis_track="verify" 未被 _required_ai_evidence 识别，两条通路都使 verify 候选系统性落入 unresolved/pending——核验轨在裁决层功能性失效，而 A-6 的预期（"unresolved/pending"）恰好掩盖该缺陷。回退与预算设计本身健全；可实施性存在伪码缺异常捕获、早退绕过 checkpoint 尾部记账等中等问题。**R-1/R-2/R-3 构成同一根因链，须在实施前修订方案并重设 A-6 为生产路径端到端验收。**

## 2. 问题清单

**【R-1】【关键】** D5"聚合层 path#window 兜底"不成立——适配证据将被聚合层全量判 invalid（CONTEXT_ID_NOT_FOUND → AI_EVIDENCE_REF_INVALID critical gap 白名单外 → verify 候选永不采信）。
证据：evidence.py:707-714（slice_refs 循环内窗口正则）；orchestrator.py:1147（slice_refs=final_slice contexts）；evidence.py:669-674/425-426。
修订建议：`_verify_candidate` 成功分支显式注入 `candidate["ai_evidence_contexts"]`=适配窗口 contexts（kind="code_window"——evidence.py:669-674 已支持优先读取）；同步修订 D5 论证。

**【R-2】【高】** analysis_track="verify" 未被 `_required_ai_evidence` 识别 → 恒发 AI_EVIDENCE_REQUIREMENTS_UNRESOLVED critical gap（白名单外）——即使证据全部有效 supports 也只能 unresolved。
证据：evidence.py:507-538（仅 l1_triage/l2_review 分支）；decision.py:65-131（白名单无此 code）。
修订建议：`_required_ai_evidence` 将 track="verify" 按 l2_review 语义取 requirements；验收增加"干净 verify 候选可达 supported"正向断言。

**【R-3】【高】** A-6 验收设计与生产路径脱节（直接调 validate_ai_evidence_references 自构造 contexts + 预期 unresolved/pending——恰是 R-1/R-2 失效模式输出，测试通过≠生产可用）。
证据：验收方案 A-6；evidence.py:21-76（生产路径 verify_candidate → _ai_evidence_contexts）。
修订建议：A-6 改端到端：verify 适配候选 → `verify_candidate(candidate, code_index, reader)` → `DecisionEngine().decide`——断言 invalid_evidence_refs 为空且非因证据校验失败 unresolved。

**【R-4】【中】** verify 成功早退绕过 analyze_job 尾部记账（_append_ai_trace("candidate_completed")/trace_store.save_completed——无 checkpoint 持久化、缺 trace 收尾事件）。
证据：orchestrator.py:547-572；实施方案 §3.3 伪码。
修订建议：`result = verify_result if ... else await self._analyze_with_expansion(...)` 统一走原尾部。

**【R-5】【中】** N-3/N-4 期望的异常捕获在伪码缺失（仅 try/finally——异常上抛 worker FAILED 兜底，非验收预期）。
证据：实施方案 §3.3；验收 N-3/N-4。
修订建议：verify+adapt 整体 try/except Exception → verify_fallback_reason="verify_error" 返回 None。

**【R-6】【中】** D2 理由失实：分析层 guard_status 仅落 ai_guard_assessment（决策层零消费），"absent 会增强"无代码路径；且丢弃了核验 guard_effective 命题判定信号。
证据：decision.py:382-391（gate 读候选级确定性 guard_status）；orchestrator.py:1150。
修订建议：修订 D2 论述（"决策层不消费、仅审计展示的诚实缺省"）；溯源字段记录 guard_effective 命题结论。

**【R-7】【中】** CallTreeSettings 用默认实例偏离先例（deep-dive 用 explorer.call_tree——用户调过 explorer.call_tree.max_depth 时行为分裂）。
证据：orchestrator.py:960；config.py:174-178/196-203。
修订建议：复用 `self.settings.explorer.call_tree`（与 deep-dive 同源）。

**【R-8】【低】** `_run_ai_stage` 签名变更波及 6+ 处测试调用点（位置传参无默认值即破坏）。
证据：test_ai_preflight.py:340/388/430/487/569；test_explorer.py:640。
修订建议：code_index 设默认 None。

**【R-9】【低】** 验收文档基线数字自相矛盾（A-17 写 1073，实际 1103）。
修订建议：统一 1103。

**【R-10】【低】** budgeted 回调三处重复 + verify 缺墙钟检查（单轮路径有 max_candidate_wall_seconds）。
证据：orchestrator.py:936-953/1032-1033。
修订建议：抽公共工厂；墙钟缺失注明（轮数有界，D 记录）。

**【R-11】【低】** fallback=False 失败终态缺 ai_stop_reason/ai_analysis_trace（原路径有——前端/审计对齐）。
证据：orchestrator.py:702-724。
修订建议：对齐补齐两字段。
