## 1. 评审结论摘要

方案总体质量高：设计决策均有代码先例支撑、与 T0.8/T1.1 表结构逐列核对一致、范围边界干净。但存在**一处高危逻辑缺陷**：内容寻址副本路径按 sha256 共享，二次注册同 APK 时"INSERT 冲突后清理已写副本"会误删既有资产的唯一副本（并发场景更会删掉正在使用的副本），且风险表回退方案自相矛盾。另有限值注入不完整、测试与验收负例脱节等 7 项。修复 R-1/R-3 后实施。

## 3. 认可项

- 内容寻址副本 vs asset_id 目录取舍正确（UNIQUE 同源防重、删除无引用计数、与 run 隔离副本语义清晰）。
- ConflictError 而非幂等返回（409 + details.asset_id 供 T1.4 跳转提示）正确。
- registry 注入 repository 复用 connect()（统一事务/FK/WAL）、package_name 调用方提供（注册期解析需反编译过重）、enabled 门禁归 API 层，均与既有代码风格一致。
- 表结构/约束/索引与 T1.1 迁移逐列一致；A-8 FK SET NULL 测试可行；N-2 文件名白名单识别到位（registry 拼路径风险面大于 storage）。
