## 1. 评审结论摘要

方案锚点准确、决策链清晰，D1/D2 主干成立。两处高严重度缺陷：**R-1** 并发模型表述自相矛盾且技术上不成立（storage.ingest 为同步 def，协程内直接调用阻塞事件循环，拷贝期间全部在跑 scan 停摆）；**R-2** run_batch 伪码遗漏 create_run 建行步骤（ingest 仅写 manifest，建行在 routes），且 runs 三列 UPDATE 无归属模块（update_run 白名单不含这些列）。另 A-16 等价性保障前提（既有 config 快照测试）经核实不存在。修订后进入实施。

## 3. 认可项

- 锚点全部核实无误（batches 表/runs 三列/BatchSettings/run 级熔断/summary→manifest/ingest）。
- D2 计数走 manifest 持久化优于进程内属性（`_ai_requests_used` 为每实例态，跨 run 不可复用）；A-9 篡改 runs 重算设计到位。
- D1 否决"创建即 ingest"理由成立；v5 延续 v4 幂等加列 + 逐条 execute 风格一致。
- orchestrator_factory 每资产 new 成本可控（构造轻量；ai_runtime 显式传入不误关共享运行时）。
- 降级复用 `ai.enabled=false` 贴合方案原文；D5 trace_id=batch_id、D6 崩溃恢复克制；FakeOrchestrator 注入点充分。
