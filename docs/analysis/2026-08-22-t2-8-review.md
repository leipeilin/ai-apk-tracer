## 1. 评审结论摘要

两份方案与大纲 §2.4/§2.2/§5.4/§5.5 及 M2 验收 4.3-5.4（"hops 不变仅新增证据"）高度一致：D1 不自动升级、D2 仅 partial 送深挖、链不可变测试锚点均成立，未见越权收紧。协议层/驱动先例锚点逐一核实无误，`_invoke_prompt` 零改动复用、缓存 no-op 判断、`--write` 再生成机制均属实。主要缺口在可实施细节：证据回查所需 reader/db 通道未定义（R-1）、停滞判定首轮误伤且与 R-3 自述矛盾（R-2）、多轮累积可击穿 schema 上界（R-3）、allow_external_code 门禁指代不明（R-4）、批次级熔断短路缺失（R-5）。验收点 A-1~A-16/N-1~N-7 均可判定。结论：**补齐 R-1~R-5 后可进入实施**。

## 2. 问题清单

**【R-1】【中】** 证据回查/文件行切片需 files 表访问，但 ExplorerOrchestrator 仅持有 call_tree（reader 为其私有成员），方案未定义 db 通道。
证据：backend/app/analysis/explorer.py:47-59；explorer_validation.py:27-32（先例以参数收 reader）；实施方案 §3.1/§3.3.3。
修订建议：`deep_dive_partials(candidates, reader)` 增参或构造注入；禁止穿透 `call_tree._reader`。注入时机本身正确（validate 后、save 前、reader try 块内存活期内）。

**【R-2】【中】** 停滞判定"本轮无新增 confirmed/refuted 即终止"使首轮全 still_unknown 直接终止，损失第 2 轮 callees 扩展上下文；R-3 自述风险（"首轮全 still_unknown 但第二轮能突破"）未被其缓解措施覆盖；验收 A-8② 用"连续"、实施用"本轮"，口径冲突。
证据：实施方案 §3.3 伪码、§3.6 R-3；验收方案 A-8。
修订建议：停滞判定加 `round_index≥2` 前置（或"连续两轮无新增"），统一两文档措辞。

**【R-3】【中】** 跨轮累积无上界策略：ExplorerCandidateDeepDive.evidence_refs max=64、remaining_gaps max=32，而单轮 DeepDiveOutput 各自上限 64/32，4 轮累积可达 256/128，结果模型构造即 ValidationError（被容错吞为 failed）；rounds max_length=4 硬复制 config 默认值，而 `explorer.max_requests_per_candidate` 无 le 上限，调大即断。
证据：实施方案 §3.2；backend/app/analysis/ai_models.py:451-458；backend/app/config.py:191。
修订建议：明确去重/截断+计数策略；rounds 上界放宽（如 16）或循环钳制 min(config, schema)。

**【R-4】【中】** allow_external_code 门禁指代不明：存在 ai.allow_external_code（ai.py:884 全局熔断）与 explorer.allow_external_code（config.py:187，当前后端零使用）两键；T2.5b 探索循环 code_context 从未按 explorer 键门禁，深挖单方面加门禁致同轨口径分裂。
证据：explorer.py:118-128（无门禁）；config.py:68/187；实施方案 §3.3.2、验收 A-5。
修订建议：明确使用 explorer.allow_external_code（对齐大纲 §5.5），探索循环补同门禁或记入已知差异。

**【R-5】【中】** 批次级熔断短路未定义：探索循环对 circuit_breaking/skipped 短路剩余入口，深挖批次未规定——预算耗尽后每 partial 候选仍完整组装上下文再判 skipped；auth 类熔断时每候选重复真实失败调用。
证据：explorer.py:136-141；实施方案 §3.3 容错边界（仅单候选语义）。
修订建议：补"熔断/预算耗尽→剩余候选批量 skipped"规则及对应验收点。

**【R-6】【低】** §3.3 集成片段三处错误：`explestrator` 命名与后续 `orchestrator` 不一致；deep_dive_partials 声明为 async（§3.2）但片段漏 await；`if explorer_settings.enabled:` 冗余——_run_explorer_stage 唯一生产调用点已在 enabled 门内。
证据：实施方案 §3.3 片段；orchestrator.py:222-224。
修订建议：修正片段防照抄引入 bug；删除冗余门控。

**【R-7】【低】** 复核账本导出口径未闭合：ai_analysis summary 的 explorer_requests_used 快照将含深挖调用（标签语义漂移）；大纲 §2.4 复核账 = ai_stage_requests_used + deep_dive_requests_used 需跨阶段求和，方案未给公式。
证据：orchestrator.py:397-400、641-643；实施方案 §3.3 记账。
修订建议：快照拆 explorer/deep_dive 两键或写明三本账导出公式。

**【R-8】【低】** 大纲引用错位：partial 处置实文在 §2.5/§5.4（"送深挖或人工高优，不直接进正式 finding"），§5.3 是候选 Schema 草案；deep_dive_entry 硬编码 "1.0.0" 与 config.deep_dive_prompt_version 无运行时绑定（沿 explore_entry 先例；漂移时 render 显性熔断，test_config.py:150 有注册对齐护栏，风险可控）。
证据：大纲 §5.3(417 行)/§5.4(463-473 行)；ai.py:443-449；config.py:192。
修订建议：引用改 §2.5/§5.4；config 描述注明声明性或 split 传入。

**【R-9】【低】** 首轮 existing_evidence_refs 构成未显式定义：T2.6 只校验 hops 不校验 chain_proposal.evidence_refs，"回查通过的证据池"初始项来源需明确；验收无对应断言。
证据：explorer_validation.py:104-139（仅跳回查）；实施方案 §3.3。
修订建议：明确初始池=chain_proposal.evidence_refs 经 §3.3.3 过滤存活项，补验收断言。

## 3. 认可项

1. D1 论证扎实：三档是确定性门禁结论、AI 判定不得改写（大纲 §2.2）；行号修正受"不改 hops"约束不可实现的推理正确；与 M2 4.3-5.4 一致。
2. D2/D3/D4 有据：D2 直接由 §5.4"unverified→人工队列不占 AI 预算"支撑；D3 证据语义=源码位置、调用边属 T2.6 职责；D4 靠 rounds 全量 output 留原始证据可审计。
3. 预算架构正确：run 级共享池复用 T2.7 R-1 模式，deep_dive_requests_used 分账可审计，A-15 恒等式可判定。
4. _invoke_prompt 复用属实：五参签名完全覆盖；RepairInput 枚举已含 DeepDiveOutput；registry 变量名与 `_prompt_variable` 推导一致。
5. 缓存 no-op 判断正确：DeepDiveOutput evidence_refs 非空时 `_evidence_refs_valid(…,None)` 恒 False、空时 bool 检查失败。
6. A-3/A-14 与现状吻合：链不可变逐字节对比对齐 M2 锚点；归一化隔离与 explorer_normalization.py partial_kept 行为一致。
7. 回查双形态路径（原样+剥 sources/ 前缀）对齐既有 `_strip_sources_prefix` 口径。
8. 边界与代码事实吻合：get_method_body 确不支持按行定位、files 行切片替代成立；N-7/方法体缺失跳过可行。
9. R-4 体积自洽：rounds≤4 × max_output_tokens 实际约束体积，全量保审计+回退（改摘要）明确。
10. 兼容与门禁：deep_dive_call 默认 None 不扰既有 4 参构造与 1053 基线；sync-ai-protocol --write 覆盖 explorer_candidate.schema.json 再生成核实可行。
