## 1. 评审结论摘要

方案主干成立：类型契约与后端实际响应逐字段核对一致，轮询感知链路（batch 置 scanning → 前端 interval 判定）经代码验证可行。主要修订点：D1"刷新丢失"论证有缝隙（`GET /api/batches/{id}` 已存在，恢复最近批次无需列表端点——URL query 即可承载）、A-6 降级场景不可复现（未写构造方法）、批量发起后选中/授权清理缺失、postFormData 等价性缺口（进度契约 + responseText 既有隐患）。修订后实施。

## 3. 认可项

- 轮询感知链路成立（batch 置 scanning/写 last_run_id/终态回写 与 interval 判定模式吻合）。
- 类型固化可靠（Asset/BatchSummary 与后端实际输出逐字段一致，test_assets_api.py 断言契约）。
- D3 正确（503 与网络错误分支区分）；双确认与后端安全语义同构非冗余。
- createBatch 走 request() 自动补 Content-Type；normalizeList 复用正确。
- 不引入测试框架与现状一致（build=tsc -b）；B-2=953 与基线吻合。
